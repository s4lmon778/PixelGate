## Findings and browser adaptation

| Topic                         | LocalSend evidence                                                                                                                                                                                                          | SpeedGate decision                                                                                                                                                                               |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Communication                 | [Protocol v2.2](https://github.com/localsend/protocol/blob/62bd3406ec80d62f2ed46269cdc06c4dcc391083/README.md): multicast announcements / HTTP registration; only one side must host an HTTP server                         | Browsers lack multicast sockets and TCP listeners. Use explicit same-origin helper URL plus existing six-digit consent flow; do not scan the LAN                                                 |
| Preparation and authorization | Metadata-only prepare request; receiver returns session and per-file tokens; bytes sent only after acceptance                                                                                                               | Separate short-lived receiver/sender bearer capabilities and explicit receiver approval before opening byte streams                                                                              |
| HTTP/TCP streaming            | [v1.18.2 client](https://github.com/localsend/localsend/blob/af0416be50770a97760f7070684bc667b759a15c/packages/core/src/http/client/mod.rs): content stream wrapped in HTTP body, source errors fail the request            | Bounded binary `Uint8Array` POSTs. Avoid whole-file arrays, base64 and request `ReadableStream` dependencies; Safari remains supported                                                           |
| Concurrency                   | [v1.18.2 upload isolate](https://github.com/localsend/localsend/blob/af0416be50770a97760f7070684bc667b759a15c/packages/localsend_isolates/lib/src/isolate/child/upload_isolate.dart): pool of **2 concurrent files**        | Default **2 concurrent checkpoint POSTs**, configurable 1–4. Keep one active receiving file and existing hash/write ownership                                                                    |
| Buffering                     | [v1.18.2 save path](https://github.com/localsend/localsend/blob/af0416be50770a97760f7070684bc667b759a15c/packages/core/src/http/server/common/save.rs): bounded upload channel (16 items), **512 KiB** buffered file writer | Node request/response backpressure; no helper body accumulation. Browser one-MiB frames/checkpoints, four-MiB durable receive window, existing worker staging                                    |
| Encryption and identity       | Native client pins certificate fingerprint and carries a client identity; protocol supports HTTPS. Native self-signed trust is managed by the app                                                                           | Browser-managed, trusted same-origin HTTPS. Never copy native “accept/pin self-signed peer” behavior into fetch or disable browser security. Helper terminates TLS and is trusted with plaintext |
| HTTP version and pooling      | v1.18.2 client explicitly advertises HTTP/1.1, disables proxy lookup and redirects. Its source comment identifies HTTP/2 flow-control limits                                                                                | Built-in Node HTTPS/HTTP/1.1 keep-alive; browser owns connection reuse. No request redirects. Respect ordinary browser connection limits; do not claim universal HTTP/2 inferiority              |
| Integrity                     | Protocol permits SHA-256 and a mismatch response; save path hashes and checks declared size                                                                                                                                 | Retain SpeedGate's stronger existing source hash + close/reread stored copy + distinct destination/export verification scopes                                                                    |
| Cancellation                  | Source cancellation tokens, bounded channels and session/operation lifecycle guards release pending work                                                                                                                    | Abort browser fetches, revoke both endpoints and destroy pending helper streams on disconnect. Preserve receiver checkpoints; never replay uncertain HTTP messages blindly                       |
| Resumption                    | Protocol v2 upload endpoint is a raw file body; this is not a specification of SpeedGate's checkpoint/resume scheme                                                                                                         | Retain receiver-owned durable offsets and source reselection/rehashing. HTTP transport is a new SpeedGate protocol, not native LocalSend interoperability                                        |

LocalSend's current repository also contains WebRTC functionality. This investigation focuses on its HTTP implementation; it does not assume every LocalSend path uses the same transport or claim that switching protocols alone fixes an iPhone/Pixel bottleneck.

## License handling

LocalSend's [source license at the inspected release](https://github.com/localsend/localsend/blob/af0416be50770a97760f7070684bc667b759a15c/LICENSE) is Apache-2.0. SpeedGate's HTTP implementation is original TypeScript/Node code informed by architectural observations and protocol concepts. No LocalSend implementation, binary, web asset or source file was copied or bundled, so the existing SpeedGate MIT license is unchanged. Attribution and upstream links are also recorded in [third-party notices](../public/third-party-notices.txt). The protocol repository had no standalone LICENSE at the inspected revision; its prose/examples were not copied into the implementation.

## What this does not establish

REA static inspection does not measure LocalSend's runtime throughput or prove that the installed binary exactly matches the release source. Automated browser and Mac loopback measurements do not replace physical iPhone Safari → Pixel Chrome measurements. The user's reported approximately **3 MB/s** on the previous browser version remains a separate, uninstrumented physical-device baseline.
